# 学什么、学到哪里就停

目标分开：赛前能交付可靠 AI 模块并与陌生队友集成；长期形成小任务、契约、测试、独立审查、可回退提交的习惯。
这里的优先级按剩余准备时间与复用价值排序，不是完整游戏开发课程。比赛日期按你提供的 10/31–11/2，不推测主办方最终工具或规则。

## P0：先完成这些可验收动作

| 项目 | 为什么 / 这次的具体价值 | 长期能否复用 | 掌握到什么程度 | 更简单的替代 | 动手证明 |
| --- | --- | --- | --- | --- | --- |
| Git 小步协作与恢复 | 看清 AI 改了什么；三人不互相覆盖；坏版本可撤销 | 所有代码项目 | status、diff、add、commit、branch/switch、merge、revert；知道提交≠push | 每人独立 clone；先不学 worktree、rebase | 在临时仓库制造同文件冲突，解决后跑测试；revert 一次错误提交且保留历史 |
| 五字段小任务 + 读代码再改 | 把“帮我做游戏”变成可验收改动；避免 Agent 自行扩张范围 | Python/Web/AI 都适用 | 能指出 Goal、Scope、验收和测试；只对复杂任务写 3 步计划 | 两句话包含目的和验收也可；模板是边界，不是表格考试 | 用 docs/TASKS.md 的 Bug 例子，让 Agent 只改约定文件；检查 diff |
| 共享规则 + 权限边界 | 两种 Agent 行为一致；防止误删、依赖膨胀和凭证泄漏 | 换仓库仍有用 | 区分自然语言规则、工具审批和沙箱；知道全局/项目/局部规则 | 单 Agent + 一份 AGENTS.md；无需 Skill/MCP 平台 | 新会话不提示答案，要求报告自动加载的规则标记；Gemini 用 /memory show 核对 |
| 客观检查 + 独立 Review | 15 小时里靠工具快找回归；不用等另一模型可用 | 最值得保留的长期习惯 | 修改后运行相关测试；新上下文看 diff；区分失败、跳过、未验证 | 没有 Lint/类型系统就先语法检查 + 核心行为测试；不为门面加工具 | 故意让“最后一回合到终点”判负，测试应红；修复后全绿，再独立审查 |
| AI 适配器、契约、Validator、Mock、超时、Fallback | 你负责模块时队友可并行接假数据；网络断了演示仍能继续 | API/Web/后端都通用，你已熟悉，重点是交接 | 输入只含必要观察；输出仅是建议；枚举/范围/状态再验证；一次有界请求 | 一个纯函数 + 假响应 + Python 标准库；不用 Agent 框架 | 用假的 429、超时、非法行动测试，证明游戏不崩；无密钥走完一局 |
| 最小 JS / 浏览器边界 | 能看懂队友的状态调用与 async，不会把 Python 同步习惯硬套前端 | 通用 Web 能力 | const、对象/数组、import/export、事件、Promise/async/await、fetch；能读懂 practice | 不必赛前掌握 TS、构建链和框架；需要时查语法 | 解释 game.js 的 act 为什么不改旧对象；解释 app.js 的 revision 为什么能防旧响应 |
| Gemini CLI 日常操作 | 主办方若只给 Gemini，你能直接交付而不是现场研究配置 | 后续 Coding Agent 都可复用概念 | 启动、认证、看 diff、规则检查、切换/退出 Plan、起新会话；保留审批 | 小任务直接交互模式；Subagent/Headless 由现成脚本承担 | 登录后完成一个小 Bug 任务，再开新会话 Review；不要依赖长聊天 |
| 运行说明、状态与演示退路 | 陌生队友能在几分钟内运行你的模块；你离开时别人能继续 | 通用团队习惯 | README 写启动/验证/环境变量名；STATUS ≤15 行；至少一个可运行提交 | 一页 README + 几行状态；不搭知识库 | 让不了解代码的人只看 README 启动 Mock；模拟网络断开仍能操作 |

调整理由：你已经懂 JSON Schema/超时等，不需要重学概念；把它们作为 P0 的交付约束。现场能否运行 Gemini 和看懂少量 JS 也不能等到 P1。离线演示退路虽很贴比赛，但对任何 API 应用同样重要，提升到 P0。

工具选择的现实约束：本机 Gemini CLI 个人 Google 登录已被服务拒绝，见 AGENT-CONFIG.md。P0 是会使用现场实际可用的 Coding Agent/认证方式，不是坚持某个已不可用的登录入口。现在可用 Codex 练通用流程；Gemini 需主办方或有效 API/企业凭证，不先额外学习新 IDE。

## P1：有时间再增加效率

| 项目 | 为什么 / 黑客松价值 | 长期价值 | 达标程度 | 更简单替代 | 动手证明 |
| --- | --- | --- | --- | --- | --- |
| Headless、只读 Subagent、Plan 深入 | 自动收集审查证据，节省重复描述 | 高，但不必自己写编排框架 | 会用现成命令，知道新进程≠独立模型，Plan 不自动代表零工具权限 | 新会话 + diff + 测试输出；Review 输入完整时可禁用所有工具 | npm run review:pack 后用同一 MODEL_ID 做 review:gemini，查看权限策略实测 |
| Agent 调试/重构与成本 | 用复现、缩小范围替代反复“再试一次”；减少延迟与 token | 高 | 先红测试/最小复现；重构保持行为；查看 stats 与耗时 | 一次只问一个问题；确定性工作用脚本 | 让 Agent 提取一个纯函数，测试不变；比较整仓库输入与小 diff 的字节数 |
| TypeScript / 深入 JS | 多人接口渐多时类型有帮助 | 高，但赛前迁移成本可能高于收益 | 理解类型、联合类型、异步返回；不是重写现有样例 | JS + 清晰对象形状 + Validator + 测试 | 给 decision 定义类型并解释运行时为什么仍要 Validator；可只写草稿不迁移 |
| worktree、简单 CI、缓存/重试 | 独立工作目录/自动测试减少互扰；缓存减少 API 延迟 | 高 | 用到时查：worktree add/remove；一次 CI；429/5xx 最多有限重试 | 三人各自 clone；本机 verify；练习默认不自动重试 | 先读 docs/TEAM.md；用一次失败输入证明不缓存错误，不重复消耗玩家回合 |

重试不是“所有失败重试三次”：401/403、非法 JSON 不重试；429/暂时 5xx 可按 Retry-After/退避重试最多一次，且受总时限控制。生成式调用可能再次计费。当前练习选择无自动重试、立即回退，现场更可预测。

## P2：等比赛方案需要时再学

| 项目 | 为什么 / 黑客松价值 | 长期价值 | 达标程度 | 更简单替代 | 动手证明 |
| --- | --- | --- | --- | --- | --- |
| 2D 引擎、Game Loop/Scene/Input/Collision | 只有实时移动、碰撞或动画较多时引擎才明显省力 | 对游戏项目可复用，普通后端较少 | 能读 update(dt)、场景切换、碰撞回调；不用先学完整 Phaser | 原生回合制；练习只有 render + act，不需要每帧循环 | 在白板画输入→状态更新→渲染；说出 AI 网络请求为什么不能放每帧等待 |
| 游戏中的 AI 角色与资源/回合 | 把生成能力接进玩法，同时保持规则稳定 | 状态机/事件/异步思维通用 | 模型提议、规则裁决；成功/失败/重开；旧请求失效 | 每回合一次结构化建议，不先做自主 NPC 系统 | 运行 practice，AI 四步通关；请求中重开，旧决策不能污染新局 |
| 15 小时文件责任、素材与演示 | 减少最后一小时合并/素材路径/网络事故 | 短期团队方法可复用 | 现场共同决定 A/B/C；素材有来源、许可、尺寸/路径；留完整演示时间 | CSS 色块或占位图；一个玩法循环；README 人工演示步骤 | 一人改前端、一人假 AI、一人测试，先用 Mock 联调；离线演示 90 秒 |

Phaser 只是候选，不是本次准备的默认引擎；Python 后端也只是帮助你利用已有能力的练习选择。正式项目若队友熟悉别的栈，保留契约与适配器思路即可。

## 建议的赛前安排：约 5–6 小时，可压缩

`npm run practice:git` 已可实际生成隔离 Git 练习仓库，演示真实冲突→解决→revert。脚本执行成功不等于你已掌握；对照打印的命令，亲自解释一次 diff 和合并图，再重复操作。

1. **45 分钟 Git**：在独立临时仓库做 branch→merge 冲突→修复→revert，别拿当前成果练破坏性恢复。
2. **45 分钟 Agent**：登录 Gemini、/memory show、新会话规则标记；用五字段修一个小 Bug。
3. **90 分钟练习代码**：先只读 game.js/ai.py；手动通关、Mock AI 通关、重开竞态、跑测试。
4. **60 分钟接口练习**：不用真实密钥也可注入 429/非法决策；用陌生队友视角解释契约。
5. **45 分钟独立 Review**：执行检查→生成 packet→相同 Gemini 模型的新会话 Review→修复→复验。
6. **30 分钟交接/演示**：只靠 README 启动，断网演示一次；记录还不会的三个问题。

如果只剩 2 小时：优先 2、3 的最小部分和一次 Mock 接口联调，不开始 Phaser/TS 课程。

## 现场约 15 小时预算（团队协商用，不是预定企划）

| 累计时间 | 团队产物 |
| --- | --- |
| 0–1h | 对主题、工具权限、AI 必须参与的玩法、验收与分工达成一致 |
| 1–3h | 最小可玩闭环 + AI 契约 + Mock 联调，保存可运行提交 |
| 3–8h | 生成式 AI 实装；你的核心产物是可替换模块、Validator、异常与调用边界 |
| 8–11h | 三人合并、游戏状态与 AI 故障测试 |
| 11–13h | 冻结新功能，修缺陷，准备素材和演示 |
| 13–15h | 留作集成缓冲、离线退路、正式讲解练习 |

你可以表达更擅长 AI Integration，但先问队友优势，再决定文件负责人。早期的可玩闭环比先分配三个抽象“大模块”更能发现接口问题。
